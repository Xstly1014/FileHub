# FileHub · 功能规格与开发交接文档（PRD）

> 本文档面向**开发 agent / 工程师**，用于直接上手实现 FileHub 可视化文件管理工作区的全部功能。
> 文档包含：技术选型建议、全局设计 Token 与路由约定、以及 **30 个功能章节**（10 必备 + 20 创意）。
> 每个功能均给出：价值 / 最终目标 / 交互逻辑 / 数据模型 / 后端·AI 接入点 / 验收标准 / 依赖与风险。
>
> 配套的**前端可交互原型**已在 `filehub/` 中实现（零依赖单页应用，模拟数据驱动），
> 可通过 `#/lab/<id>` 路由预览每个功能的交互效果，原型代码见 `js/features.js`。

---

## 一、技术选型建议（给开发 agent 的参考）

| 层 | 推荐 | 说明 |
|---|---|---|
| 前端框架 | **React + TypeScript** | 组件化、利于长期维护与接后端 |
| 画布引擎 | **React Flow** 或 **tldraw** | 承载拖拽 / 连线 / 无限画布 / 小地图 / 力导向 |
| 状态管理 | Zustand / Redux Toolkit | 画布状态、历史栈、协同状态 |
| Agent / AI | **LangChain（Python 或 JS）** | 摘要、标签、语义关联、问答（RAG） |
| 向量库 | Qdrant / Milvus / pgvector | 文件切片向量化，支撑语义检索与去重 |
| 存储 | 本地文件系统（**D 盘**）+ 对象存储 | 用户文件落盘，元数据入库 |
| 协同 | WebSocket + CRDT（Yjs） | 多人光标 / 操作实时同步 |
| 离线 | PWA（Service Worker + Background Sync） | 离线优先、本地缓存、后台同步 |
| 检索 | PostgreSQL FTS / ElasticSearch | 全文检索与高亮 |

> 约束（来自需求）：**所有开发资源放在 D 盘，禁止写入 C 盘**；语言选型以最适配为准；
> 实现允许先用简单方案，但要在代码中保留 `TODO` 痕迹，方便后续替换升级。

# 五、功能章节

## 必备功能（已集成进外壳，真实可用）

### E1 暗色模式（Dark Mode）
- **价值**：护眼 + 用户偏好持久化。
- **最终目标**：主题切换无缝、记忆偏好；深/浅两套视觉对比度达标（WCAG AA）。
- **交互逻辑**：顶栏 🌙 按钮或设置中心切换 → `documentElement[data-theme=dark]` → 重写 CSS 变量；`localStorage` 记忆。
- **数据模型**：`theme: 'light' | 'dark'`（localStorage `fh_theme`）。
- **后端接入点**：无（纯前端）。
- **验收标准**：切换即时生效；刷新后保持；所有主要表面（顶栏/侧栏/画布/详情/弹窗）正确反色。
- **依赖与风险**：硬编码色需全部改为变量（已用 `dark.css` 覆盖核心表面）。

### E2 命令面板 ⌘K（Command Palette）
- **价值**：键盘优先的高效操作，降低鼠标依赖。
- **最终目标**：80% 的高频操作可通过命令面板 3 秒内完成。
- **交互逻辑**：`Ctrl/Cmd+K` 唤起 → 输入模糊匹配命令 → ↑↓ 选择 → ↵ 执行 / Esc 关闭。
- **数据模型**：命令列表 `Command[] {icon,title,run()}`（见 `app.js` `cmdCommands`）。
- **后端接入点**：无。
- **验收标准**：支持搜索/键盘导航/执行；命令可扩展注册。
- **依赖与风险**：命令需集中注册，避免散落。

### E3 撤销 / 重做（Undo / Redo）
- **价值**：操作可回溯，降低试错成本。
- **最终目标**：画布所有变更（移动/连线/删连线/删除节点/恢复）可逐步撤销重做。
- **交互逻辑**：`Ctrl+Z` 撤销、`Ctrl+Shift+Z` 重做；每次变更前快照（节点坐标+连接+存在集）。
- **数据模型**：`history: Snapshot[]`，`Snapshot{pos,conns,ids}`, `hi:number`（指针）。
- **后端接入点**：可选——协同场景下需 OT/CRDT 合并。
- **验收标准**：连续撤销/重做到基线无错乱；越界有提示。
- **依赖与风险**：快照粒度为整画布，大画布需增量或节流。

### E4 响应式 / 移动端（Responsive）
- **价值**：多端可用。
- **最终目标**：桌面/平板/手机均可用，窄屏不溢出、可操作。
- **交互逻辑**：`<1480px` 整体缩放适配；`<760px` 收起顶部导航、压缩搜索框。
- **数据模型**：无（CSS 媒体查询）。
- **后端接入点**：无。
- **验收标准**：主流视口下布局完整、可点击。
- **依赖与风险**：固定 1440×900 绝对布局的响应式是「缩放适配」演示；真移动端需流式重排（建议 React 后用 flex/grid 重构）。

### E5 设置中心（Settings）
- **价值**：集中偏好管理。
- **最终目标**：外观/AI 模型/存储路径/密度统一配置并可持久化。
- **交互逻辑**：⚙️ 或命令面板打开 → 分区表单 → 更改即时生效（主题联动 E1）。
- **数据模型**：`settings{theme,aiModel,storagePath,density}`（localStorage）。
- **后端接入点**：AI 模型选择需对接后端配置；存储路径固定 D 盘。
- **验收标准**：各选项生效并记忆。
- **依赖与风险**：存储路径展示为 D 盘，真实写入受浏览器沙箱限制（需本地应用/后端）。

### E6 通知中心（Notifications）
- **价值**：团队/个人变更同步。
- **最终目标**：变更（批注/关联/AI 更新/备份）实时触达，未读可辨。
- **交互逻辑**：🔔 打开下拉时间线；未读红点；打开后标记已读。
- **数据模型**：`Notification[]{text,time,unread}`（原型为静态 seed）。
- **后端接入点**：WebSocket 推送 + 通知服务。
- **验收标准**：展示/已读/红点正确。
- **依赖与风险**：真实需事件总线与权限过滤。

### E7 新手引导（Onboarding）
- **价值**：零学习成本上手。
- **最终目标**：新用户首次进入 5 步内理解核心操作。
- **交互逻辑**：首次进入分步遮罩（欢迎→排版→连线→AI 总结→打开编辑）→ 下一步/跳过；`localStorage` 记忆已看。
- **数据模型**：`onboardDone:boolean`（localStorage `fh_onboard`）。
- **后端接入点**：无。
- **验收标准**：仅首次显示；可跳过；步骤文案准确。
- **依赖与风险**：升级后引导内容需可版本化。

### E8 回收站（Trash）
- **价值**：防误删。
- **最终目标**：删除文件可恢复或彻底删除，零数据意外丢失。
- **交互逻辑**：选中节点按 Delete → 移入回收站（侧栏入口）→ 列表可恢复/彻底删除。
- **数据模型**：`App.trash: Node[]`；节点含 `id/name/type` 等。
- **后端接入点**：软删除 + 回收站 TTL。
- **验收标准**：删除→回收站可见→恢复回到画布；彻底删除不可恢复。
- **依赖与风险**：需与 E3 撤销协调（恢复应入历史栈）。

### E9 导出 / 备份（Export）
- **价值**：数据可携带与本地留存。
- **最终目标**：一键导出工作区为 JSON / PNG / PDF，备份到本地。
- **交互逻辑**：⤓ 或命令面板 → 生成 JSON Blob 触发下载（PNG/PDF 标注 TODO）。
- **数据模型**：`{files,connections,exportedAt}`。
- **后端接入点**：PNG 用 html2canvas；PDF 用后端渲染或 jsPDF。
- **验收标准**：JSON 可再导入；PNG/PDF 真导出。
- **依赖与风险**：浏览器下载落用户目录，非直接写 D 盘（需本地应用/后端写盘）。

### E10 快捷键体系（Shortcuts）
- **价值**：专业效率。
- **最终目标**：高频操作均有快捷键，可查阅。
- **交互逻辑**：`?` 打开快捷键面板；列出 ⌘K / 撤销重做 / Esc / Delete / Enter 等。
- **数据模型**：`kbData[][key,desc]`（静态）。
- **后端接入点**：无。
- **验收标准**：面板内容与真实快捷键一致；可扩展。
- **依赖与风险**：与命令面板（E2）共享快捷键注册表最佳。

## 创意功能（Feature Lab 完整可交互原型，`#/lab/<id>`）

### C1 力导向自动布局（force-layout）
- **价值**：从混乱到有序，零手动整理。
- **最终目标**：混乱度下降 80%，整理耗时从分钟级降到秒级。
- **交互逻辑**：「打乱」随机散布 → 「一键整理」模拟受力动画，关联紧密节点聚簇 → 可继续微调。
- **数据模型**：节点坐标 + 连接；聚类按连通分量分组。
- **后端接入点**：d3-force / 力导向物理引擎实时迭代。
- **验收标准**：整理后簇内紧凑、簇间分离；动画流畅。
- **依赖与风险**：大规模节点需 WebGL/虚拟化。

### C2 时间轴回放（timeline）
- **价值**：理解知识演进，可回溯任意时刻。
- **最终目标**：用于复盘/演示/审计；任意历史快照可还原。
- **交互逻辑**：底部时间轴展示事件序列 → 拖动/播放逐步回放（加入/移动/关联）→ 画布仅显示截至时刻内容。
- **数据模型**：`TimelineEvent[]{day,type:'add'|'move'|'link',nodeId,x,y,a,b,label}`。
- **后端接入点**：操作日志 / 事件溯源（Event Sourcing）。
- **验收标准**：回放与真实操作顺序一致；可定位快照。
- **依赖与风险**：需全量操作日志存储。

### C3 无限画布 + 小地图（infinite-canvas）
- **价值**：海量文件不丢失空间感。
- **最终目标**：缩放/平移操作占比下降，定位效率提升。
- **交互逻辑**：空白拖拽平移 → 滚轮以光标为中心缩放 → 右下角小地图显示全局与视口框 → 点小地图跳转。
- **数据模型**：视口 `{offsetX,offsetY,scale}`；节点世界坐标。
- **后端接入点**：无（前端）；十万级节点需瓦片/虚拟化。
- **验收标准**：平移/缩放平滑；小地图视口框同步。
- **依赖与风险**：大画布性能（虚拟化渲染）。

### C4 空间锚点记忆（anchors）
- **价值**：个人化工作空间，快速进入心流。
- **最终目标**：多场景（评审/写作）布局一键切换。
- **交互逻辑**：拖到满意位置 → 保存为锚点（命名）→ 点锚点按钮带动画恢复布局。
- **数据模型**：`Anchor[]{name,layout:{nodeId:{x,y}}}`。
- **后端接入点**：用户偏好存储（按用户维度）。
- **验收标准**：保存/恢复准确；多锚点管理。
- **依赖与风险**：锚点冲突/合并策略。

### C5 画布模板（templates）
- **价值**：从空白到结构化，降低启动成本。
- **最终目标**：新用户首屏即用，冷启动时间下降。
- **交互逻辑**：选模板（项目启动/读书笔记/研究调研）→ 生成节点骨架+示例关联 → 可继续编辑。
- **数据模型**：`Template[]{name,desc,nodes[],links[]}`。
- **后端接入点**：模板库云端同步 + 用户自定义。
- **验收标准**：生成结构正确；可编辑。
- **依赖与风险**：模板与真实文件映射。

### C6 AI 语义关联推荐（ai-links）
- **价值**：隐性关系显性化，自动织网。
- **最终目标**：关联覆盖率提升，用户手动连线减少。
- **交互逻辑**：选文件 → 右侧按相似度列出候选 → 「连接」建立关联（画布实时连线）/「忽略」剔除。
- **数据模型**：`Suggestion[]{targetId,sim}`。
- **后端接入点**：**embedding 向量相似度（LangChain + 向量库）** 替换模拟分数。
- **验收标准**：推荐相关；连接即时生效。
- **依赖与风险**：向量化成本与时效。

### C7 AI 跨文件问答（ai-chat）
- **价值**：从被动浏览到主动问答。
- **最终目标**：回答可追溯，找信息时间大幅下降。
- **交互逻辑**：提问 → AI 流式回答 → 答案下列出引用来源卡片 → 点来源跳详情。
- **数据模型**：`ChatMessage[]{role:'q'|'a',text,refs[]}`。
- **后端接入点**：**LangChain RAG（检索增强生成）**，跨文件切片检索。
- **验收标准**：回答含引用；来源可跳转。
- **依赖与风险**：幻觉控制、引用准确性。

### C8 AI 摘要胶囊（ai-capsule）
- **价值**：秒懂内容，减少打开成本。
- **最终目标**：用户平均少打开 60% 文件即可获取要点。
- **交互逻辑**：悬停节点 → 浮层胶囊显示实体/待办/结论 → 移开消失 → 点节点进详情。
- **数据模型**：`Summary{entities[],todos[],conclusion}`。
- **后端接入点**：**LangChain 结构化抽取**（实体/待办/结论）。
- **验收标准**：胶囊内容准确且精简。
- **依赖与风险**：抽取准确率。

### C9 智能标签推荐（ai-tags）
- **价值**：零维护元数据。
- **最终目标**：标签覆盖率 100%，手动打标时间趋近于零。
- **交互逻辑**：选文件 → AI 建议标签（可勾选）→ 应用写入 / 手动增删。
- **数据模型**：`tags[]{t,c:'blue'|'gray'}`。
- **后端接入点**：分类模型 / LLM 零样本打标。
- **验收标准**：建议相关；应用正确。
- **依赖与风险**：标签体系治理。

### C10 AI 封面生成（ai-cover）
- **价值**：视觉化记忆，快速识别。
- **最终目标**：文件识别速度提升，工作区更具归属感。
- **交互逻辑**：选文件夹/文档 → 「生成封面」→ 模拟出图（渐变+图标）→ 填充节点/卡片。
- **数据模型**：`cover:imageUrl`。
- **后端接入点**：**文生图模型（DALL·E / Stable Diffusion）** 语义封面。
- **验收标准**：封面稳定生成并与内容相关。
- **依赖与风险**：出图成本/时延。

### C11 重复 / 近似检测（dedup）
- **价值**：清理知识库，避免版本混乱。
- **最终目标**：重复文件减少，存储与认知负担下降。
- **交互逻辑**：「扫描」→ 列出相似对+相似度 → 「合并」保留其一删副本 / 「忽略」。
- **数据模型**：`DuplicatePair[]{a,b,sim}`。
- **后端接入点**：内容哈希 + 语义向量去重，文件夹级比对。
- **验收标准**：检测准确；合并安全。
- **依赖与风险**：误合并风险（需二次确认）。

### C12 文件健康度评分（health）
- **价值**：识别陈旧/孤立文件，主动维护。
- **最终目标**：知识库健康度可量化、可运营。
- **交互逻辑**：节点角标显示综合分 → 点开看维度条（新鲜/关联/完整）→ 低分提示待维护。
- **数据模型**：`Health{score,fresh,link,complete}`。
- **后端接入点**：基于修改时间/关联数/内容完整性的实时评分模型。
- **验收标准**：评分合理；维度可解释。
- **依赖与风险**：权重需可调。

### C13 协同光标与在场（presence）
- **价值**：团队知识共建、实时在场感。
- **最终目标**：远程协作同步率提升。
- **交互逻辑**：画布显示多人彩色光标（随机游走模拟）→ 头像列表在线成员 → 「跟随」某人光标。
- **数据模型**：`Collaborator[]{name,color,cursor{x,y}}`。
- **后端接入点**：**WebSocket / CRDT（Yjs）** 实时同步光标与操作。
- **验收标准**：多光标实时；跟随可用。
- **依赖与风险**：并发冲突解决（CRDT）。

### C14 批注便签（sticky）
- **价值**：上下文讨论，沉淀决策。
- **最终目标**：评论与文件空间绑定，决策可追溯。
- **交互逻辑**：「＋便签」→ 画布点击落点生成可编辑便签 → 输入（支持 @ 提及高亮）→ 拖拽/删除。
- **数据模型**：`StickyNote[]{x,y,text,mentions[]}`。
- **后端接入点**：便签持久化 + 评论线程 + @通知。
- **验收标准**：增/改/删/拖动可用；@渲染。
- **依赖与风险**：与协同（C13）合并评论系统。

### C15 分享与权限（share）
- **价值**：安全对外协作。
- **最终目标**：分享可控、可撤销，泄露风险下降。
- **交互逻辑**：选文件 → 「生成链接」→ 权限（只读/可编辑）+ 过期时间 → 复制分享 / 可撤销。
- **数据模型**：`ShareLink[]{token,perm,expiry,revoked}`。
- **后端接入点**：签发带权限/过期的签名 URL + 访问审计。
- **验收标准**：权限生效；过期/撤销有效。
- **依赖与风险**：越权访问（需严格服务端校验）。

### C16 双向链接 / 反向链接（backlinks）
- **价值**：构建个人知识网络（Obsidian 式）。
- **最终目标**：文件间关系可双向追溯。
- **交互逻辑**：选文件 → 预览正文 `[[引用]]` → 右侧反向链接面板列「谁引用了我」→ 点来源跳转。
- **数据模型**：正文 `[[名称]]` 引用；`backlinks: Map<id, name[]>`。
- **后端接入点**：解析引用图谱 + 自动维护反向索引。
- **验收标准**：双向可达；引用解析准确。
- **依赖与风险**：重命名文件的引用更新。

### C17 关系图谱视图（graph）
- **价值**：全局视野发现隐藏关联。
- **最终目标**：跨聚类洞察，知识网络一目了然。
- **交互逻辑**：切图谱模式 → 节点力导向布局 → 连线表达关联（簇=主题社区）→ 拖拽调整 → 点节点进详情。
- **数据模型**：图 `nodes + edges`（同源文件与连接）。
- **后端接入点**：社区发现算法 + 大规模图渲染。
- **验收标准**：布局稳定；可交互。
- **依赖与风险**：大图性能（WebGL）。

### C18 智能收藏夹（smart-fav）
- **价值**：快速回到重要文件。
- **最终目标**：常用文件触达时间缩短。
- **交互逻辑**：手动收藏归入「手动」区；AI 按访问频率自动置顶「常驻」区 → 点跳详情 / 可移出。
- **数据模型**：`favorite:boolean` + `smartFavorites:id[]`（访问频次统计）。
- **后端接入点**：埋点统计访问频率，定时重算常驻。
- **验收标准**：分区正确；常驻随使用更新。
- **依赖与风险**：频次统计隐私。

### C19 全文检索高亮（fulltext）
- **价值**：大海捞针。
- **最终目标**：跨文件内容检索命中率与速度提升。
- **交互逻辑**：搜索框输入 → 匹配名/摘要/正文 → 结果列表展示命中片段（高亮）→ 点结果画布节点闪烁定位。
- **数据模型**：索引 `content` 全文。
- **后端接入点**：**全文索引（ElasticSearch / PostgreSQL FTS）**。
- **验收标准**：检索快；高亮准确；定位闪烁。
- **依赖与风险**：大语料索引构建。

### C20 PWA 离线优先（pwa）
- **价值**：随时随地可用、数据不丢。
- **最终目标**：离线可用率 100%，弱网体验无缝。
- **交互逻辑**：切换「离线模式」观察状态 → 离线改动写本地存储 → 恢复网络本地优先同步 → 可「安装到本地」。
- **数据模型**：`localCache{ts,files}`（localStorage 演示）。
- **后端接入点**：**service-worker.js + manifest.webmanifest + Background Sync**。
- **验收标准**：离线可开；改动本地优先；安装可用。
- **依赖与风险**：缓存一致性、冲突解决。
